# Terminal interface validation — 2026-10-08

The interface uses explicit operation identifiers from the existing migration
commands. Its disk drawings describe the algorithm; colored transfer tiles
represent logical byte counters, not a sampled physical extent map. Unknown
byte totals remain unknown. The installer has no additional runtime dependencies.

## Automated checks

- 12 progress tests: subprocess copying and hashes, counters, resized PTYs,
  narrow recovery consoles, Unicode widths, failure/interruption, cursor
  restoration, stale process detection, plain logs and retained backup instructions.
- 17 strategy tests: recommendations, explicit flags, controlling-terminal input,
  arrow keys, multi-digit destinations, unavailable methods, manual confirmation,
  and prompts that remain idle beyond 15 seconds.
- 17 encryption tests: default-off behavior, explicit key sources, saved-key
  retyping, cancellation, hidden input and key lifecycle.
- Python compilation, shell syntax, focused ShellCheck, generated installer
  equality and SHA-256 verification.
- Boot-argument/GRUB and network fixtures run inside Ubuntu. The macOS controller
  lacks `grub-script-check` and `ip`; those probes were rerun in the guest.

## Native ARM64 runtime

Disposable QEMU/HVF VMs, Ubuntu 24.04, UEFI, 1 GiB RAM. No shared host folders or
host disk passthrough. The root guest used Linux `6.8.0-146-generic` and OpenZFS
`2.2.2-0ubuntu9.5`.

| Case | Result |
| --- | --- |
| 25 GiB root, 71% used; automatic slice-by-slice recommendation | Copy, complete-manifest verification, native block relocation and ZFS boot passed |
| Root preservation | Bytes, accounts, shadow, SSH host keys, ACLs, xattrs, hard links, sparse files and configuration passed `verify-preserved.sh` |
| Root recovery setup | `verify.sh` passed; installed snapshot and growth service present; pool is one native partition |
| Root scrub and another reboot | Zero checksum errors; both verification scripts passed again |
| 8 GiB attached disk; 50/50 conversion | SHA-256, hard links, symlink, sparse data, full-disk growth and original mount point preserved; OS remained ext4 |
| Attached disk after reboot | ZFS mount and all file hashes passed |
| Final packaged root setup | Method preview, encryption choices and final review exercised on an ext4 guest; cancellation left `/` ext4 and created no migration work directory |
| Native rescue console | Final renderer displayed actual migration state through `/dev/console`; state and disk contents were read only |

The long root conversion started with a development UI build. Presentation was
refined during the run; the final viewer read its live counters independently.
Final setup, keyboard behavior, compact rendering and console output were also
checked separately. The conversion algorithms and their verification gates were
not changed by this interface work.
